# STORM Release Manager

## Обязательные правила при создании и редактировании релизов:
1. **Заголовок релиза (`name`) и тег (`tag_name`)**:
   - Поле `name` релиза ВСЕГДА строго: `<APP_NAME> <VERSION>` (например: `STORM SWITCH BOX 5.1.0`, строго ЗАГЛАВНЫМИ БУКВАМИ и **без префикса `v`**).
   - Поле `tag_name` строго: `<VERSION>` (например: `5.1.0`, без `v`).
   - Запрещено указывать в `name` просто номер версии (`5.1.0`) или префикс `v` (`v5.1.0`).
2. **Строгая 4-блочная структура описания (`body`)**:
   - **Блок 1**: `> 💡 **Релиз <VERSION>** — *<Краткая ёмкая сводка ключевых нововведений и улучшений релиза курсивом>.*`
   - Разделитель `---`
   - **Блок 2**: `### 🚀 Ключевые исправления и улучшения (<APP_NAME> <VERSION>)` + категоризированный список с указанием затронутых файлов.
   - Разделитель `---`
   - **Блок 3**: `<details><summary><b>🌐 English Changelog (click to expand)</b></summary>` с заголовком `### 🚀 Key Improvements & Fixes (<APP_NAME> <VERSION>)`.
   - Разделитель `---`
   - **Блок 4**: `<details><summary><b>📦 Файлы и вложения к релизу (нажмите, чтобы развернуть)</b></summary>` с точными размерами в МБ и контрольными суммами `SHA-256`.
3. **Запрет дублирования H1 и подписей**:
   - Никогда не помещать тег `# H1` в начало `body`.
   - Не добавлять фразы «Собрано и опубликовано автором...» в конце.
4. **Сохранение ассетов и двойные переносы строк**:
   - Сохранять 100% прикреплённых файлов (`_Setup.exe`, `.zip`) и оставлять пустые строки вокруг `<summary>` и `</details>`.
